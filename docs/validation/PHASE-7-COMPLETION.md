# Phase 7 — embedded dashboard completion

Status: **COMPLETE within the approved bounded scope**, 2026-11-06.
This is local implementation completion, not release-wide acceptance.

## Authorization and delivered scope

The user approved [the Phase 7 proposal](../PHASE-7-PROPOSAL.md) with
“Let continue working on phase 7. you have my aproval”.
[ADR 0017](../decisions/0017-embedded-local-dashboard.md) records the accepted
transport, security and asset strategy. See [DASHBOARD](../DASHBOARD.md) for usage,
runtime approval, limits and operational recovery.

Delivered:

- Optional reviewed `velnix ui` foreground launch, loopback API and embedded Vue
  dashboard with Overview, Projects, Runtimes, Owned services, Certificates,
  Mail and Diagnostics pages. No permanent daemon or hosted deployment.
- Typed shared application reads/actions, without CLI/TUI text parsing or a
  terminal process owner masquerading as a browser session. Page reads create
  no persistent state and perform no executable probes.
- Private single-use bootstrap, expiring in-memory sessions, host-only HttpOnly
  SameSite cookies, exact Host/Origin and CSRF checks, forwarded/cross-site
  rejection, bounded JSON/work/connection handling and restrictive local CSP.
- Session-bound expiring plan tickets, explicit exact-ID apply, replay/stale-state
  rejection, session mutation serialization and non-retrying uncertain outcomes.
  Accepted mutations use bounded application contexts independent of browser
  disconnect. Existing backend journals/ownership/locks remain authoritative.
- Reviewed initialization, project link/unlink, exact native runtime selection/
  clear and mail pruning. Runtime probe execution is disclosed before Apply.
- Public workload/certificate DTOs without health tokens, private keys or Mailpit
  credential/session paths. Unavailable capabilities remain explicit.
- Passive plain-text mail viewing, exact authenticated attachment downloads,
  safe download names and preserved Phase 6 pruning/no-egress behavior.
- Responsive navigation, keyboard/modal focus, light/dark themes, explicit
  refresh/cancellation and stale-read suppression, no credential storage and no
  background polling or remote browser resources.

The approved proposal explicitly permits a safe fallback when hostile HTML
preview cannot be demonstrated. **HTML preview is unavailable** in this release:
there is no sanitizer dependency, iframe or insertion of sender HTML into the
Vue DOM. Browser mail viewing is plain text and safe downloads. This limitation
is visible in the product and documented, not represented as HTML support.

## Tooling and generated assets

Pinned Bun 1.4.4; exact Vue 3.5.45, Vite 8.3.6, plugin-vue 6.0.10,
TypeScript 6.0.3, vue-tsc 3.3.14 and Playwright 1.65.0 in `web/package.json`
and committed `web/bun.lock`. Vite/Vue/vue-tsc are MIT-licensed;
TypeScript/Playwright are Apache-2.0. Vue runtime notices are copied into the
embedded assets at `/assets/licenses.txt`. No Go dependency was added.
Broader release license/security review remains a separate release gate.

`sh scripts/build.sh` performs frozen install, typecheck/frontend build and Go
compilation. Tracked generated assets allow clean-clone Go-only builds/tests;
`check-dashboard-assets.py` rebuilds and compares all generated bytes. CI uses
pinned Bun setup, frozen install, exact asset/size checks and browser acceptance.
The modified hosted CI workflow has not been executed as a hosted run here.

Final compressed JS+CSS measured **41,582 bytes**, below the existing 250 KiB
budget. Production assets reproduce exactly locally. There is no placeholder
embed, production Node/Bun server or runtime frontend download.

## Executed local validation

Environment: unprivileged Linux/WSL, Ubuntu 26.04 metadata, amd64, Go 1.27.3,
Bun 1.4.4. Browser: Playwright Chromium 158.0.8127.18 at desktop 1440×1000 and
mobile 390×844, with a separate mail check at the default browser viewport.
Disposable state/projects/inboxes were used; no existing inbox was inspected or
pruned and no external Mailpit instance was adopted.

```sh
sh scripts/build.sh
python3 scripts/check-dashboard-assets.py
go vet ./...
VELNIX_TEST_MAILPIT=/usr/local/bin/mailpit go test -race -count=1 ./...
VELNIX_UI_BINARY=/absolute/velnix VELNIX_TEST_MAILPIT=/usr/local/bin/mailpit \
  bun run --cwd web test:browser
python3 scripts/validate-dashboard.py bin/velnix
python3 scripts/validate-mail.py bin/velnix
git diff --check
```

Results:

- Full Go race suite **PASS**, including existing real PHP/FPM/Nginx/runtime
  checks, real Mailpit persistence/count/age retention and recovery, and the new
  web/application/runtime-file tests. Application package about 140 seconds
  locally; no performance budget inferred from test duration.
- New API tests **PASS**: unauthorized reads/downloads, hostile Host/Origin,
  forwarded headers and cross-site metadata, login CSRF/rate/expiry, session
  cookie flags/logout/idle expiry, JSON/body limits, unknown fields/routes,
  plan session isolation/expiry/replay/staleness, accepted apply after request
  cancellation and forced-download headers. Private runtime permissions,
  bootstrap consumption and refusal to delete modified runtime evidence pass.
- Three actual browser tests **PASS**: login, initialization, project linking,
  externally invalidated stale review, native Python selection/clear, all seven
  pages, cookie-based reload, logout, light/dark screenshots, keyboard review
  cancellation/focus, mobile menu closure and no horizontal overflow. No page
  exceptions or CSP violations in the desktop flow. No API polling during the
  recorded idle observation and no auth data in browser persistent storage.
- Real mail browser test **PASS**: multipart plain-text inspection with hostile
  HTML/remote-image content present in the captured message; no iframe or
  external browser requests; safe attachment basename and byte-exact `0001ff`
  download; irreversible-prune review/cancellation. Capture remains a separate
  explicitly approved CLI child. Mail test skips explicitly when its provider
  environment flag is absent, as in the default CI browser run.
- Built CLI acceptance **PASS**: read-only launch preview, bad approval rejection,
  occupied-port refusal, private bootstrap, authentication/Host/Origin/CSRF,
  passive reads leaving state absent, logout revocation, Ctrl-C exit 130,

  capture/restart/crash/recovery acceptance also passes with the new binary.
- Typecheck, frozen install, frontend build, reproducibility/size, Go vet/build,
  gofmt and whitespace checks **PASS**. Desktop light/dark, mobile and mail
  screenshots were inspected visually; browser layout claims are not inferred

One local built-UI sample measured a warm launch of **30.01 ms** and **13,916 KiB

## Limits and open release work

Plain loopback HTTP is not encrypted. Sessions/runtime files do not provide
kernel, same-UID or general hostile-local-code isolation. The Phase 6 no-egress
boundary remains policy for approved flows, not unused authenticated provider
features. HTML preview, browser-owned workload lifecycle, remote access/TLS,
provider/package installation, config editing, database/system-service actions
and host integrations remain excluded. Registry schema/ownership grants did not
change. Mail deletion still has no general undo.

Other browsers and real mobile devices, native Ubuntu/non-systemd, Windows/WSL
network variants, comprehensive resource exhaustion/slow-client/filesystem fault
injection, broader dependency/license/security review and hosted CI/release
packaging remain open in [RELEASE-ACCEPTANCE](RELEASE-ACCEPTANCE.md).
Phase 8 requires separate scope approval; this record does not authorize it.
